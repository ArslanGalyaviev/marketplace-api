# Marketplace API

Это мой проект для домашнего задания №2. Делал API для товаров на Python и FastAPI.

Я выполнял **пункты 1–6 и 8**: OpenAPI, CRUD товаров, генерацию кода, PostgreSQL с миграциями, обработку ошибок, валидацию и логирование запросов. Пункты **7, 9 и 10** (заказы, JWT и роли) не реализовывал.

## Что умеет API

- `POST /products` — добавить товар.
- `GET /products/{id}` — получить товар по ID.
- `GET /products` — получить список товаров с пагинацией (`page`, `size`) и фильтрами (`status`, `category`).
- `PUT /products/{id}` — изменить товар.
- `DELETE /products/{id}` — архивировать товар. Запись из базы не удаляется, только меняется статус на `ARCHIVED`.

У товара есть название, описание, цена, количество на складе, категория, статус и даты создания и обновления.

## Что использовал

- **Python 3.12, FastAPI** — само API.
- **Pydantic** — модели и проверка входных данных.
- **OpenAPI (YAML)** — описание запросов, ответов и ограничений.
- **PostgreSQL 16** — хранение товаров.
- **Liquibase** — создание таблицы, индекса и триггера для `updated_at`.
- **Docker Compose** — чтобы запускать всё вместе.

## Как запустить

Нужен установленный и запущенный Docker.

В папке проекта выполнить:

```bash
docker compose up --build
```

При запуске поднимается PostgreSQL, Liquibase применяет миграции, после этого запускается API. Генерация моделей и роутов выполняется при сборке образа.

После запуска можно открыть:

- Swagger UI: http://localhost:8000/docs
- OpenAPI FastAPI: http://localhost:8000/openapi.json

Для остановки:

```bash
docker compose down
```

## Как проверить

Можно отправлять запросы через Swagger или запустить мой скрипт:

```bash
python scripts/check.py
```

Скрипт проверяет основные случаи: создание товара, получение, список с фильтрами, обновление, ошибку валидации, мягкое удаление и ошибку 404. **Не все граничные случаи покрыты этим скриптом.**

Также можно посмотреть записи прямо в базе:

```bash
docker compose exec db psql -U student -d marketplace
```

А потом выполнить:

```sql
SELECT * FROM products ORDER BY id;
SELECT * FROM products WHERE status = 'ARCHIVED';
```

Для выхода из `psql` — `\q`.

## Генерация кода

Основной контракт находится в `openapi/products.yaml`. Скрипт `scripts/generate.py` читает его и создаёт модели Pydantic и роуты FastAPI в `app/generated/`.

Если нужно сгенерировать код отдельно, можно выполнить (при установленных зависимостях из `requirements.txt`):

```bash
python scripts/generate.py
```

Папка `app/generated/` добавлена в `.gitignore`, потому что эти файлы не пишутся вручную, а создаются генератором.

## Ошибки и валидация

В OpenAPI указаны ограничения для полей, например: цена должна быть больше нуля, остаток — неотрицательный, у названия и категории есть ограничения длины.

При неправильных данных API возвращает `400` с `error_code: VALIDATION_ERROR` и информацией об ошибочных полях. Если товара с таким ID нет, возвращается `404` с `PRODUCT_NOT_FOUND`.

## Логирование

Для запросов добавил middleware. Логи пишутся в JSON: метод, путь, статус ответа, время выполнения, `request_id`, `user_id` и время запроса. Для `POST`, `PUT` и `DELETE` также записывается тело запроса. Если в JSON есть пароли или токены, они маскируются, в том числе во вложенных объектах и массивах.

В ответе приходит заголовок `X-Request-Id`. Авторизации в проекте нет, поэтому `user_id` пока `null`.

## Структура проекта

- `openapi/products.yaml` — OpenAPI-спецификация.
- `scripts/generate.py` — генерация моделей и роутов из YAML.
- `scripts/check.py` — простые проверки API.
- `app/main.py` — создание FastAPI, обработчики ошибок и логирование.
- `app/handlers.py` — работа с товарами и SQL-запросы к PostgreSQL.
- `db/changelog/changelog.xml` — миграции Liquibase.
- `Dockerfile` — сборка приложения.
- `compose.yaml` — запуск API, базы и миграций.
- `requirements.txt` — зависимости Python.
